# Hermes Codex 브리지 관계도

이 저장소의 브리지 소스만 다룬다. 테스트 파일은 구조·줄 장부에서 제외하고, ReloginTool은 `gateway/codex_bridge/handoff.py`가 읽는 계약까지만 추적한다. 소스 구조와 실제 배포·전달 상태를 구분한다.

1. 먼저 [구조 개요](../../../docs/codex-bridge/overview.md)의 범위, 검증한 소스 커밋, 관계도를 읽는다. 실행·SQLite 상태가 필요한 질문에서만 [흐름 문서](../../../docs/codex-bridge/flows.md)의 관련 절을 읽는다. 세부 줄은 [장부](../../../docs/codex-bridge/coverage.tsv)에서 파일·함수명으로 검색한다.
2. 개요의 검증 커밋부터 현재 `HEAD`까지의 비테스트 소스 diff와 작업 트리의 변경을 확인한다. 해당 변경이 없으면 기존 문서를 사용한다. 변경이 있으면 바뀐 줄과 연결된 호출자·피호출자·상태 전이를 확인하고 영향받은 관계도와 설명을 갱신한다. 다른 작성자의 커밋이 섞이면 Git diff 전체를 사용자 자체 구현으로 단정하지 않는다.
3. 사용자가 전수 재검증을 요구하면 기준점 이후의 대상 비테스트 코드 전체를 다시 읽고, 모든 변경 줄과 함수의 관계를 대조한다. 일반적인 질문이나 소규모 수정에서는 전체 장부를 읽지 않는다.
4. 커밋된 소스가 바뀌면 `python3 .agents/skills/hermes-codex-map/scripts/build_coverage.py --base a6102b8d809d6b32824757b547b60f9d22d6a88e`로 장부를 재생성하고, `--check`로 Git 추가 줄 합계와 일치를 확인한다. 문서의 검증 커밋은 실제로 재확인한 소스 커밋으로만 올린다. 미커밋 소스 변경은 별도 표시하고 검증 커밋에 포함시키지 않는다.
5. 결과에는 바뀐 경로와 근거, 남은 미검증 경계만 간결하게 적는다. 운영 중이라는 주장은 운영 프로세스·배포 파일·전달 기록을 별도로 확인한 경우에만 한다.
